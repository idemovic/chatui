chatui integration guide npm install + static config

Embed chatui in your app

This guide walks you through installing chatui from an npm tarball (or local file path), mounting the widget in your React app, and configuring every option statically in code. No runtime config fetch, no settings UI needed.

1. Prerequisites

chatui ships as a pre-built ESM bundle with its CSS pre-compiled. The host needs:

  • React 19 (peer dependency)
  • Any modern bundler that supports ESM and JSON package exports (Vite, Webpack 5+, esbuild, Rollup, etc.)
  • Node 18 or newer (for installing the package)
No Tailwind required, and no stylesheet to load. chatui inlines its CSS into the JS bundle and injects it into a shadow root at mount time, so your host page never sees chatui's styles and chatui never sees yours.

2. Install

Option A: from a tarball (recommended for sharing)

Run npm pack in the chatui repo to produce chatui-X.Y.Z.tgz. Then in your host:

npm install /absolute/path/to/elia-assistant-chatui-0.0.1.tgz

Option B: local file path (recommended for parallel development)

In your host's package.json:

{
  "dependencies": {
    "@elia-assistant/chatui": "file:../chatui"
  }
}

Then run npm install. Edits in the chatui repo reflect in the host after a dev-server restart.

Option C: from a CDN — no install, no bundler

The package ships an IIFE bundle with React + ReactDOM included. Drop two lines into any HTML page and you're done. jsdelivr and unpkg auto-mirror the published package once it's on npm: 

<script src="https://cdn.jsdelivr.net/npm/@elia-assistant/chatui/dist/chatui.iife.js"></script>
<script>
  Chatui.createChat({
    webhookUrl: 'https://your-n8n.example.com/webhook/abc',
    mode: 'window',
  })
</script>

The target option (CSS selector or element) is optional. When omitted, createChat appends a new <div> to <body> automatically and mounts the widget inside a shadow root attached to that div. If you prefer an existing element, pass its selector as shown below.

See section 4 below for the full createChat() API. unpkg.com works the same way: https://unpkg.com/@elia-assistant/chatui/dist/chatui.iife.js.

Minimal host package.json

chatui's bundle already includes i18next, react-i18next, react-markdown, remark-gfm, zustand, and the pre-compiled CSS. Don't redeclare them in your host — doing so risks duplicate copies. The host needs only React, the bundler, and chatui itself: 

{
  "scripts": {
    "dev":   "vite",
    "build": "tsc -b && vite build"
  },
  "dependencies": {
    "@elia-assistant/chatui": "file:../chatui/elia-assistant-chatui-0.0.1.tgz",
    "react":                  "^19.0.0",
    "react-dom":              "^19.0.0"
  },
  "devDependencies": {
    "@types/react":        "^19.0.0",
    "@types/react-dom":    "^19.0.0",
    "@vitejs/plugin-react": "^6.0.0",
    "typescript":          "~5.9.0",
    "vite":                "^8.0.0"
  }
}

Add back only if you need them in your own host code (not for chatui to work):

PackageAdd when
i18next + react-i18nextYou want to register extra locales at runtime (see Languages section) or use useTranslation in your own components.
zustandYour host code has its own Zustand stores.
tailwindcss + @tailwindcss/viteYour host's own UI uses Tailwind. chatui doesn't need it — its CSS is already compiled.

3. Minimal mount

createChat() is the entry point for every integration, React or not. It builds the widget's state, translations and shadow root, and hands back an instance you can reconfigure or unmount later. Pass your configuration straight to the call. 

// src/ChatWidget.tsx
import { useEffect, useRef } from 'react'
import { createChat, type ChatInstance } from '@elia-assistant/chatui'

export function ChatWidget() {
  const containerRef = useRef<HTMLDivElement>(null)
  const instanceRef  = useRef<ChatInstance | null>(null)

  useEffect(() => {
    if (!containerRef.current || instanceRef.current) return

    instanceRef.current = createChat({
      target:      containerRef.current,
      webhookUrl:  'https://your-n8n.example.com/webhook/abc123',
      mode:        'window',
      botName:     'Support',
      streaming:   true,
      theme:       'midnight',
      language:    'en',
    })

    return () => {
      // Deferred so StrictMode's double-invoke doesn't unmount mid-render.
      const instance = instanceRef.current
      instanceRef.current = null
      setTimeout(() => instance?.unmount(), 0)
    }
  }, [])

  // The chat panel needs a sized parent.
  return <div ref={containerRef} style={{ height: '100vh' }} />
}
Reconfiguring later. The returned instance exposes setConfig(patch), setTheme(id), setLanguage(lang) and unmount(), so you never need to reach into the widget's internal state. There is no global store to import - see multiple widgets for why.

Raw component tree (no shadow root)

If you specifically need the widget inside your own React tree rather than a shadow root, render <App /> directly. It reads its stores and translations from context, so you build them yourself and supply both providers. Note that this path does not inject the widget's CSS for you. 

import { I18nextProvider } from 'react-i18next'
import {
  App,
  StoreProvider,
  createChatI18n,
  createSettingsStore,
  createChatStore,
} from '@elia-assistant/chatui'

// Create these once, at module scope - not on every render.
const i18n          = createChatI18n()
const settingsStore = createSettingsStore(i18n)
const chatStore     = createChatStore()

settingsStore.getState().setConfig({
  webhookUrl: 'https://your-n8n.example.com/webhook/abc123',
  mode:       'window',
})

export function ChatWidget() {
  return (
    <I18nextProvider i18n={i18n}>
      <StoreProvider settingsStore={settingsStore} chatStore={chatStore}>
        <App />
      </StoreProvider>
    </I18nextProvider>
  )
}

Without both providers <App /> throws useSettingsStore must be used within a <StoreProvider>.

About persistence. chatui persists its config to localStorage under the key chatui-settings, and its conversation history under chatui-chat. Options you pass to createChat() overwrite the matching fields on boot; unset fields keep their stored values. For a clean slate, call localStorage.removeItem('chatui-settings') before mounting.

Multiple widgets on one page

Every createChat() call owns its config, theme, UI language and conversation state, so two widgets never overwrite each other's settings. A support widget and an embedded product demo can sit on the same page and be themed independently.

They do share one localStorage, though. Pass storageNamespace to keep their persisted state apart: 

createChat({ target: '#support', webhookUrl: '...' })

createChat({
  target:           '#demo',
  webhookUrl:       '...',
  mode:             'embedded',
  theme:            'ivory',
  storageNamespace: 'demo',        // -> chatui-settings-demo, chatui-chat-demo
})
When to set it. Only when more than one instance can be mounted at once. Omit it for the usual single-widget page and the default storage keys are used, so an existing install keeps its saved settings and chat history.

Plain script tag (CDN)

From a <script> tag the global is named Chatui:

<script src="https://cdn.jsdelivr.net/npm/@elia-assistant/chatui/dist/chatui.iife.js"></script>
<script>
  Chatui.createChat({ webhookUrl: '...' })
</script>
Optional target. When you omit target (or pass a selector that does not match any element), createChat creates a new <div>, appends it to <body>, and attaches the shadow root to that div. The widget then renders inside the shadow root so its styles are fully isolated from the host page. If you want to control placement yourself, create a <div id="chat"> and pass target: '#chat'.

4. Full static configuration

Every option available, with defaults and realistic values. Drop this into the bootstrap file and delete the fields you do not need. 

import { createChat } from '@elia-assistant/chatui'

const instance = createChat({

  // ─── Mount target ────────────────────────────────────────────────
  target: '#chat',                            // selector or element; omit to append to body

  // ─── Required ────────────────────────────────────────────────────
  webhookUrl: 'https://your-n8n.example.com/webhook/abc123',

  // ─── Webhook transport ────────────────────────────────────────────
  webhookConfig: {
    method:  'POST',                           // or 'GET'
    headers: { 'X-API-Key': 'your-secret' },
  },
  chatInputKey:   'chatInput',                 // body key for the user message
  chatSessionKey: 'sessionId',                 // body key for the session id
  metadata:       { source: 'marketing-site' },  // merged into every request body

  // ─── Behavior ─────────────────────────────────────────────────────
  streaming:             false,                      // expect SSE from n8n
  showWelcomeScreen:     true,
  allowFileUploads:      false,
  allowedFileExtensions: '.pdf,.docx,.png,.jpg,.jpeg',

  // ─── Layout ───────────────────────────────────────────────────────
  mode:        'window',                         // 'fullscreen' | 'window' | 'mixed'
  position:    'right',                          // 'right' (default) | 'left' — side the widget floats on

  // ─── Bottom-sheet style (fullscreen / mixed-on-mobile) ──────────
  fullscreenSheet:       false,                      // don't fully cover the viewport; sheet docked to bottom
  fullscreenSheetHeight: '75vh',                    // any CSS length: '75vh' | '600px' | '70%'

  // ─── Appearance ───────────────────────────────────────────────────
  theme:     'midnight',                         // see Themes section
  botName:   'Assistant',                        // global fallback (per-lang overrides below)
  botAvatar: 'bubble',                            // built-in id, URL, or data URL. See Avatars section.

  // ─── CTA popup (window mode) ─────────────────────────────────────
  showCta:  true,
  ctaText:  'Hi! How can I help?',                // global fallback
  ctaDelay: 5000,                                    // ms before it appears
  ctaSound: true,                                    // Web Audio beep
  // toggleButtonIcon: 'orb',               // omit → uses same icon as botAvatar. Special ids: 'elia', 'orb', 'bubble'.

  // ─── UI lock ──────────────────────────────────────────────────────
  hideSettings: true,                                // default. Set to false to show the gear, theme picker, and settings modal.

  // ─── Tabs (Notifications + FAQ) — see "Tabs" section ─────────────
  tabs: {
    notifications: {
      title:   'Tips',
      feedUrl: '/notifications.json',            // production: hosted JSON
      // items:  [...]                            // dev alternative; URL wins if both set
    },
    help: {
      title:   'Help',
      // inline items for quick local testing
      items: [
        { question: 'How do I categorize expenses?', answer: 'Group by purpose…' },
        { question: 'How do I save receipts?',      answer: 'Snap with the app…' },
      ],
    },
    chat: { title: 'Chat' },
  },

  // ─── i18n ─────────────────────────────────────────────────────────
  // To set the initial language, call setLanguage('sk') after setConfig()
  // (or pass language: 'sk' to createChat). On a fresh browser, falls back
  // to navigator.language → 'en'.
  initialMessages: ['Hello! How can I help?'],    // global fallback
  i18n: {
    en: {
      botName:         'Sam',
      welcomeSubtitle: 'Ask me anything.',
      initialMessages: ['Hi! How can I help?', 'I speak English.'],
      ctaText:         'Try me now!',
    },
    sk: {
      botName:         'Sam',
      welcomeSubtitle: 'Opýtajte sa ma čokoľvek.',
      initialMessages: ['Dobrý deň! Ako vám môžem pomôcť?'],
      ctaText:         'Vyskúšajte ma!',
    },
  },

  // ─── Initial theme and language ───────────────────────────────────
  theme:    'cosmos',
  language: 'sk',
})

// Or change either one later, without remounting:
instance.setTheme('cosmos')
instance.setLanguage('sk')

Customizing colors

Every theme is a set of CSS custom properties. Because the widget renders inside a shadow root, host-page stylesheets cannot reach inside it - pass overrides through the cssVars config option instead. The values are applied as inline styles on the widget root and take effect immediately. Pick the closest built-in theme via config.theme, then override only the variables you care about. 

createChat({
  target:    '#chat',
  theme:     'midnight',
  cssVars: {
    '--t-accent':       '#ff5722',
    '--t-user-bubble':  '#ff5722',
    '--t-bg-base':      '#111111',
  },
})

Variables you can override:

VariableWhat it styles
--t-bg-baseOutermost background of the widget.
--t-bg-surfacePanels, input field, bot bubbles.
--t-bg-borderBorders and dividers.
--t-accentPrimary accent (send button, links, focus rings).
--t-accent-fgText color on accent backgrounds.
--t-fg-primaryPrimary text color.
--t-fg-secondarySecondary text (subtitles, hints).
--t-fg-mutedMuted text (placeholders, timestamps).
--t-user-bubbleBackground of the user's message bubbles.

Replace midnight in the selector with whichever theme id you passed to config.theme. Adding a fully new theme id (not in the table above) requires building chatui from source.

7. Avatars and toggle button icon

chatui ships 30 built-in portrait avatars, all inlined as data URLs inside dist/index.js. You can reference one by id, supply your own URL, or paste a data URL.

Both botAvatar and toggleButtonIcon accept the same value forms:

  • Built-in id — portrait avatars (sample): 'amara', 'david', 'elena', 'kenji', 'mei', 'nadia', 'priya', 'samuel', 'sofia', and ~20 more.
  • Built-in id — special/icon avatars: 'orb', 'bubble', 'bean', 'owl', 'liquidorb'.
  • URL: any http(s)://… or root-relative path such as '/img/my-avatar.png'
  • Data URL: 'data:image/png;base64,…' (what the built-in file picker produces)
Unknown id fallback. If botAvatar or toggleButtonIcon is set to a built-in id that no longer exists (e.g. an id removed from the set), the widget automatically falls back to displaying the 'bubble' icon so the UI never shows a broken image. External URLs are passed through as-is.

Toggle button icon

When toggleButtonIcon is omitted, the floating button shows the same icon as botAvatar. Set it explicitly only when you want a different icon on the button. The recommended choices are the special icon avatars: 'elia', 'orb', and 'bubble'.

When the settings UI is visible (hideSettings: false), a "Same as Bot avatar" checkbox controls this: checked = inherits botAvatar, unchecked = lets the user pick from the three special icons.

If the settings UI is visible (hideSettings: false), end users can also pick a portrait avatar, upload a file (max 500 KB), or paste a URL from the settings modal.

8. Languages

English and Slovak ship pre-bundled inside node_modules/@elia-assistant/chatui/dist/chunks/translation-*.js. The widget loads them on demand via dynamic import(), no HTTP fetch.

To register a new language at runtime (without rebuilding chatui), add the bundle to the instance's own i18next instance, exposed as instance.i18n: 

const instance = createChat({ target: '#chat', webhookUrl: '...' })

instance.i18n?.addResourceBundle('fr', 'translation', {
  welcome:  { subtitle: 'Commencez une conversation.' },
  input:    { placeholder: 'Tapez un message...' },
  // ... full keys: copy from node_modules/@elia-assistant/chatui/dist/chunks/translation-*.js
})

instance.setLanguage('fr')
Not the global singleton. Each instance owns a private i18next instance so two widgets on one page can show different UI languages. A bundle registered on the global i18next import will not reach the widget - always go through instance.i18n.

Then add any French per-language overrides under config.i18n.fr.

9. Tabs (notifications + FAQ)

The chat panel can host up to three tabs above the conversation: a Notifications feed, a searchable FAQ, and the chat itself. Tabs are fully opt-in: if neither Notifications nor FAQ has a data source, no tab bar renders and the panel looks identical to the single-pane chat.

Each tab accepts a feedUrl (JSON over HTTP, recommended for production) or items (inline array, useful while developing). When both are set, the URL wins.

Notifications feed

The endpoint at tabs.notifications.feedUrl must return:

{
  "items": [
    {
      "id":      "vat-deadline-2025",
      "title":   "Lehota na podanie DPH",
      "message": "Tvoje daňové priznanie...",
      "tags":    [{ "label": "New", "variant": "neutral" },
                  { "label": "High", "variant": "danger" }],
      "date":    "2025-07-11",
      "cta": { "url": "https://example.com/vat", "title": "Read more" }
    }
  ]
}

id, tags, date, cta are optional. title + message are required. tag.variant: 'neutral' | 'success' | 'warning' | 'danger'. Tags can also be plain strings (rendered as neutral). cta.url opens in a new tab. date is shown verbatim — format it on the server.

FAQ feed

The endpoint at tabs.help.feedUrl must return:

{
  "items": [
    {
      "id":       "expense-categorization",
      "question": "Ako mám kategorizovať firemné výdavky?",
      "answer":   "Nákupy rozdeľ podľa...",
      "category": "Výdavky"
    }
  ]
}

Search is case-insensitive substring across question + answer + category. Click a row to expand the answer.

Inline items (dev / static)

Skip the URL and pass items directly when prototyping or shipping a small static list: 

instance.setConfig({
  tabs: {
    notifications: {
      items: [
        {
          title:   'Welcome',
          message: 'Thanks for trying the demo.',
          tags:    [{ label: 'New', variant: 'success' }],
          cta:     { url: 'https://example.com', title: 'Learn more' },
        },
      ],
    },
  },
})

Per-language tab titles

Override titles per language under i18n[lang].tabs:

i18n: {
  sk: {
    tabs: {
      notifications: { title: 'Tipy'  },
      help:          { title: 'Pomoc' },
      chat:          { title: 'Chat'  },
    },
  },
}

Resolution order for each title: i18n[activeLang].tabs.X.title → tabs.X.title → built-in i18n string (tabs.notifications / tabs.help / tabs.chat).

10. Gotchas and troubleshooting

"Calling require for 'react' in an environment that doesn't expose require"

Vite 8 (Rolldown) pre-bundles node_modules packages by default. For chatui that produces a broken CJS-style interop wrapper for the externalized React peer dep. Since dist/index.js is already a finished ESM bundle, tell Vite to skip pre-bundling it: 

export default defineConfig({
  plugins: [react()],
  optimizeDeps: {
    exclude: ['@elia-assistant/chatui'],
  },
})

"Invalid hook call" or two React copies

chatui declares react and react-dom as peerDependencies. If npm installs two copies anyway (because of version mismatch), dedupe: 

npm dedupe
# or if that does not help, add to your package.json:
"overrides": { "react": "^19.0.0", "react-dom": "^19.0.0" }

Webhook is called but returns CORS errors

Your n8n Chat Trigger must allow the origin your host page is served from. Open the Chat Trigger node in n8n and add your origin under Allowed Origins (CORS).

Showing the settings gear (it is hidden by default)

For npm consumers the gear, theme picker, and settings modal are hidden out of the box, because your config is static code. If you want them back (admin dashboard, internal tools, live demo), flip the flag: 

createChat({
  target:       '#chat',
  webhookUrl:   'https://your-n8n/webhook/abc',
  hideSettings: false,
})

The widget renders but has no height

chatui uses h-full internally. Its parent container must have an explicit height, for example height: 100vh or a fixed pixel value.

Clearing persisted state during development

// DevTools console, or a temporary boot-time line
localStorage.removeItem('chatui-settings')
localStorage.removeItem('chatui-chat')

// If the instance was created with storageNamespace: 'demo',
// its keys are suffixed instead:
localStorage.removeItem('chatui-settings-demo')
localStorage.removeItem('chatui-chat-demo')

Upgrading from 1.x

2.0 removed the module-level global stores; each createChat() call now owns its state, which is what makes multiple widgets possible. CDN / Chatui.createChat() integrations need no changes, and the default storage keys are unchanged so saved settings and history carry over.

1.x2.0
useSettingsStore.getState().setConfig({...}) instance.setConfig({...}), or pass the options to createChat()
useSettingsStore.getState().setTheme(id) instance.setTheme(id)
useSettingsStore.getState().setLanguage(lang) instance.setLanguage(lang)
useChatStore from @elia-assistant/chatui/chat-store removed — no global chat store exists
i18next.addResourceBundle(...) on the global singleton instance.i18n?.addResourceBundle(...)
<App /> rendered directly still supported, but must be wrapped in <I18nextProvider> + <StoreProvider>

The ./store and ./chat-store subpath exports now expose only the createSettingsStore / createChatStore factories and their state types, so a stale useSettingsStore import fails immediately rather than at the first .getState() call.
